iPodWizard - build instructions (Microsoft Visual Studio 2005)
==============================================================

This folder holds everything needed to build iPodWizard (v1.3.4e) from source with
Microsoft Visual Studio 2005 (Visual C++ 8.0). There is no other third-party code to get:
the ZipArchive library it uses is included (zip\ and the compiled Zip.lib).


1. What you need
----------------

 * Microsoft Visual Studio 2005 with Visual C++ and MFC (Standard, Professional or Team
   System edition). The Express edition has no MFC and cannot build this program.
   The program was built and tested with Visual Studio 2005 Professional (compiler
   14.00.50727.42, linker 8.00.50727.42, resource compiler 5.2.3690.0).
 * The libraries it links come with Visual Studio 2005: the static Unicode MFC library
   (VC\atlmfc\lib\uafxcw.lib) and the bundled Platform SDK (credui, wininet, version, ...).
   If the linker cannot find uafxcw.lib, run the Visual Studio 2005 setup in maintenance
   mode and make sure the Visual C++ MFC libraries are installed.
 * The program is built for 32-bit Windows (x86). Visual Studio 2005 itself can be
   installed on a 64-bit Windows; the build scripts find it in
   "C:\Program Files (x86)\Microsoft Visual Studio 8".


2. What is in this folder
-------------------------

   *.cpp, *.h, iPodWizard.rc, resource.h   the program (Tips.txt is compiled into it
                                            as a resource, so it must stay here)
   res\                                    icons, bitmaps and the manifest used by iPodWizard.rc
   Debug\iPodService.tlh                   type library header that iPodWizard.h includes
                                            (the folder is only named Debug; keep it as it is)
   zip\                                    ZipArchive library sources (GNU GPL v2, see zip\License.txt)
   Zip.lib                                 the compiled ZipArchive library (x86, Unicode, static MFC)
   iPodWizard.sln, iPodWizard.vcproj       Visual Studio 2005 solution and project
   build_firmware.bat, build.bat           command line build (see 3)
   build_firmware_only.bat                 shortcut: compiles firmware.cpp only
   PixoNames.txt, iPW.ini                  data files the program reads from its own folder
   License.txt, ReadMe.txt                 the license (GNU GPL v2) and the program notes


3. Command line build (the build that is used for the releases)
---------------------------------------------------------------

 1. Open a command prompt in this folder. The folder can have any name and may contain
    spaces. The scripts set up the compiler themselves: they look for Visual Studio 2005
    through the VS80COMNTOOLS variable and then in the usual install folders. (If
    they cannot find it, start a "Visual Studio 2005 Command Prompt" from the Start menu
    and run them from there.)

 2. Run   build_firmware.bat
    It compiles the support source files into the Release folder (about 2 minutes) and
    ends with COMPILE OK. About 50 compiler warnings are normal.

 3. Run   build.bat
    It compiles the resources and the remaining sources, links Release\iPodWizard.exe
    (about 1 minute) and copies PixoNames.txt and iPW.ini next to it. It ends with BUILD OK.

 4. Run   Release\iPodWizard.exe

When you change the source: after editing a .cpp file run the script that compiles it
(the file lists are in the two scripts), then build.bat, which links everything. After
changing a header (.h) file run both scripts again, in the order build_firmware.bat,
build.bat. To start from scratch delete the Release folder.

The scripts build a Release configuration: optimization /O2 /Ob1 /Oi /Ot, whole program
optimization (/GL, with /LTCG at the link), static MFC (/MT), Unicode, x86. The "maximum
speed" test build of v1.3.4e used /O2 /Ob2 /Oi /Ot /Oy /GF /GL in place of
/O2 /Ob1 /Oi /Ot /GL in both scripts (change the line in both if you want the same).


4. Building in the Visual Studio 2005 IDE
-----------------------------------------

 1. Open iPodWizard.sln.
 2. Choose the Release configuration (platform Win32).
 3. Build the iPodWizard project (right click the project, Build). Building the whole
    solution also compiles the ZipArchive project; that is not needed, because Zip.lib is
    already here. The program is Release\iPodWizard.exe. (The IDE project has its own
    default optimization settings, so this exe is not byte for byte the one the batch
    build makes.)
 4. Copy PixoNames.txt and iPW.ini from this folder into the Release folder, next to
    iPodWizard.exe (the batch build does this for you).


5. Rebuilding Zip.lib (optional)
--------------------------------

Zip.lib is the ZipArchive library built from the sources in zip\. To rebuild it:

 1. Open zip\ZipArchive.vcproj (or iPodWizard.sln) in Visual Studio 2005.
 2. Choose the configuration  "Release Unicode MFC Static"  (platform Win32) and build the
    ZipArchive project.
 3. Copy the result, zip\Release Unicode MFC Static\ZipArchive.lib, over Zip.lib in this
    folder (the name changes from ZipArchive.lib to Zip.lib).

The configuration matters: the program is built with static MFC and Unicode, and the
library has to be built the same way.


6. If something goes wrong
--------------------------

 * "Microsoft Visual Studio 2005 was not found": run the script from a Visual Studio 2005
   Command Prompt, or install Visual Studio 2005 into one of the usual folders.
 * LNK1104: cannot open file "Release\iPodWizard.exe": the program is still running. Close it.
 * Unresolved external symbols or missing .obj files when linking: run build_firmware.bat
   first (build.bat only compiles part of the sources and links all of them).
 * "Cannot open include file Debug\iPodService.tlh": the Debug folder was moved or deleted.
   The file is part of the source and has to stay at that place.
 * Many warnings (C4018, C4244, C4312, ...) are normal for this code base.
